# omo V2 P3 — 事件/请求 hooks 实施计划

> **For agentic workers:** 按 task 逐个实现（TDD）；每个 task 完成后跑测试与 `tsgo`。

**Goal:** 把 omo 现有的 12 个 V1 hook handler 接到 OpenCode V2 的 hook 域上，让会话生命周期/请求变换/工具守卫行为在 V2 生效。

**Architecture:** 复用 `plugin/*` 里现成的 handler 工厂（它们只依赖 `{ctx, pluginConfig, managers, hooks, firstMessageVariantGate}`），新增一层**纯适配器**把 V2 的 hook 事件 ↔ V1 的 `(input, output)` 形状互转，再由 `register-hooks.ts` 注册到 `ctx.event` / `ctx.session` / `ctx.tool` / `ctx.permission` / `ctx.shell`。装配顺序沿用 V1：managers → tools → hooks → handlers。

**Tech Stack:** TypeScript、Bun/`bun:test`、`tsgo`、`@opencode/plugin@2.0.11`。

## Global Constraints

- 不修改 V1 路径；不改 `packages/*-core`；只在 `packages/omo-opencode/src/v2/` 新增。
- 适配器必须是**纯函数**（可单测），不直接调用 `ctx`。
- 注册必须**幂等**（`setup` 可能多次运行），并像 managers 一样在 reload 时 **dispose**。
- 桥接用的类型转换处允许一次 `as never`/`as unknown as X`（两个 SDK 的品牌类型不兼容），但必须在注释里说明理由。
- 证据：单测 + `tsgo`；**插件注入端到端 QA 在本沙箱仍不可用**（见 P2.6 的 `plugin-discovery-blocker.md`），不得声称已端到端验证。
- 仓库 `/home/user/omo-v2`；`export PATH="$HOME/.bun/bin:$PATH"`。

### Task 4c（请求 messages 转换）已探明的精确契约
V2 侧：`SessionContext.messages: Message[]`，`Message = {id, role, content: ContentPart[], metadata?, providerMetadata?, native?}`，
`ContentPart` 为 tag 联合：`text{text}` / `media{mediaType,data,filename?}` / `tool-call{id,name,input,namespace?}` /
`tool-result{id,name,result:{type:"json"|"text"|"error"|"content", value}}` / `reasoning{text,encrypted?}` / `compaction{provider,text?}` / `effort{effort?,previous?}`。

V1 侧（`hooks/tool-pair-validator/tool-part-ids.ts` + `tool-result-repair.ts` 实证）必须满足：
- tool **call** part：`{type:"tool", callID: string, state:{status: string}}`；
  `getToolUseID` 对 **terminal** 状态（`completed`/`error`）返回 `null`，对其它状态返回 `callID`
  → 所以「有配对结果的 call」要映射成 `state.status="completed"`，「缺结果的 call」要映射成 `running`
  （这样 `toolPairValidator` 才会判定缺失并修复）。
- tool **result** part：`{type:"tool_result", toolUseId, tool_use_id, isError?, content:[{type:"text",text}]}`
  （`getToolResultID` 读 `toolUseId` / `tool_use_id`）。
- `text` / `reasoning` part 直通；`categorySkillReminder` 会 `splice` 插入 `text` part。
- message 的 `info` 需带 `role`、`id`、`sessionID`（`categorySkillReminder` 读 `info.sessionID`）。

转换设计：V2→V1 时给每个 V1 part 记住其来源 V2 part（WeakMap），回写时对未映射字段做 merge 保留
（`providerMetadata`/`cache`/`native`），对 handler 新插入的 `tool_result` 生成新的 V2 `tool-result`。
